# 检查点 3：RQ1 试跑

## 结论

在 Imagenette 的 500 张验证图上，grid 说明书的预测一致率随 k 从 4 增至 64，由 **24.6% 升至 88.2%**，所有设置均高于同规模随机读取集合。K-means 在小 k 下较低，k≥16 后与 grid 接近。预设的 k≤64 范围内，两种分组都没有达到 90% 的样本一致率。

这说明选中的 token 含有保持原预测所需的信息；但同时限制全部 12 层时，很短的说明书仍会明显改变预测。当前是 P2 试跑，正式的 ImageNet 结论留到 P4。

## 设置与验收

- 分支：`feature/rq1-pilot`；运行代码提交：`b436890859e2b95b15fac3f9cf037addac27e6aa`。
- 配置：`configs/rq1_pilot.yaml`，继承正式 RQ1 设置，只将数据改为 Imagenette 160px 验证集、500 张、seed=0。
- 模型：预训练 DeiT-S，timm 默认 eval 预处理，完整 1,000 类输出；本地 RTX 4060，FP32，batch=32。
- 每层每个 head 各有 m=16 个 landmark；严格执行，全部 12 层同时限制；k∈{4,8,16,32,64}。
- grid 和 K-means 各 5 组；随机读取集合用 seed=0–4，共 25 组；合计 **35 组、17,500 条逐图执行结果**。
- 说明书从原模型中读取，执行时固定读取集合与路由。K-means 使用网格中心初始化，欧氏距离迭代 10 次；最终路由仍使用点积 argmax。
- 27 项测试通过。500 张图的 k=197 恒等一致率为 100%，最大 logit 误差为 0；每个稀疏设置也逐批验证读取 logits 与原模型完全一致，所有输出有限。
- 原模型准确率为 **82.4%（412/500）**。一致率比较的是执行前后预测是否相同，不是真实标签。
- 运行耗时 **170.7 秒**，不含启动和模型加载。

ImageNet 验证集也已下载到 `data/imagenet_val/`：50,000 张、1,000 类、每类 50 张。14 个分片的 SHA-256 校验通过；seed=0 的 5,000 张索引已固定且全部可解码，实际覆盖 994 类（随机抽样未强制类别齐全）。另用 32 张真实图片通过 CUDA 模型前向检查。数据验收记录见 `experiments/2026-10-25_imagenet_download/`；本节曲线仍是按 P2 规定使用 Imagenette 的试跑。

## 曲线与数字

![RQ1 pilot agreement](../experiments/2026-10-25_rq1_pilot/rq1_agreement.png)

随机列为 5 个种子的均值 ± 样本标准差；图中误差条同此定义。

| k | 每层每 head 的 m×k | Grid 一致率 | 随机一致率 | K-means 一致率 |
| --- | ---: | ---: | ---: | ---: |
| 4 | 64 | 24.6% | 0.32% ± 0.36 | 14.2% |
| 8 | 128 | 46.4% | 0.56% ± 0.26 | 40.4% |
| 16 | 256 | 68.0% | 2.96% ± 0.33 | 67.4% |
| 32 | 512 | 78.4% | 19.72% ± 1.05 | 79.6% |
| 64 | 1,024 | 88.2% | 51.88% ± 2.20 | 86.8% |

m×k 只计读取集合中的编号；完整说明书还包含 197 个 query 的路由，不能把这张表当作总存储量或运行加速比。

### 选对 token 有多大作用

在同一批图片上，先对随机种子取平均，再以图片为单位配对 bootstrap 1,000 次。

| k | Grid − 随机（百分点） | 95% 置信区间（百分点） |
| --- | ---: | ---: |
| 4 | 24.28 | [20.60, 28.08] |
| 8 | 45.84 | [41.44, 50.12] |
| 16 | 65.04 | [60.88, 68.96] |
| 32 | 58.68 | [55.00, 62.32] |
| 64 | 36.32 | [32.52, 40.04] |

全部区间均大于 0：在这个试跑子集上，优势不能仅用随机种子的波动解释。较大的 k 也帮助随机集合保留更多信息，所以两者的差距在 k=16 之后缩小。这里的置信区间反映图片抽样的不确定性；不是跨数据集或跨模型的保证，也没有作多重比较校正。

### Grid 与 K-means

k=4 和 8 时，grid 分别高 10.4 和 6.0 个百分点；k=16、32、64 时，两者差距分别为 +0.6、−1.2、+1.4 个百分点。当前没有看到 K-means 稳定优于空间网格的现象。

“按 query 特征分组”并不保证更忠实：本实验的 K-means 优化欧氏距离，而最终 query 路由仍按原设计使用点积。可能的解释是两种目标并不完全一致，或空间平均在小 k 时更稳定；这些是待检验的原因，当前数据不能单独区分它们。

### 90% 门槛与辅助指标

以预先约定的样本一致率判定，达到 90% 的最小 k **在本次五个测试点中未找到**。没有为跨过门槛追加更大的 k，也没有对曲线外推。grid 在 k=64 的图片 bootstrap 区间为 **[85.4%, 91.0%]**，因此 88.2% 是试跑的点估计，不能据此排除总体一致率为 90%。

![RQ1 pilot KL](../experiments/2026-10-25_rq1_pilot/rq1_kl.png)

Grid 的平均 KL 从 k=4 时的 3.716 降至 k=64 时的 0.145；K-means 在 k=64 的 KL 为 0.119，低于 grid，但 top-1 一致率略低。两者衡量不同方面：KL 看整个概率分布，一致率只看最高分的类别，所以排名不必一致。

## 与预期对照、异常及后续验证

符合设计书的两点预期：grid 明显高于随机，并随 k 增大上升。尚不支持“很短的说明书就能达到 90% 一致率”的强版本；也不属于“所有设置都很低”。这是随读取预算改善的中间结果。当前只做全层干预，不能从它判断哪些层容易或难以概括（情况 C 需要 RQ2）。

没有运行失败、NaN 或恒等检查异常。需要继续理解的现象如下，均未擅自改变预设实验：

| 观察 | 可能原因 | 如何验证 |
| --- | --- | --- |
| 小 k 的随机一致率接近零 | 随机丢弃多数连接，误差经过 12 层累积 | 在之后 RQ2 的逐层干预中检查误差是否集中于少数层；不从全层结果直接归因 |
| 小 k 时 grid 高于 K-means | 空间结构有帮助；或欧氏聚类与点积路由目标不同 | 先在预定 ImageNet 正式实验重复；若仍存在，再提议只改路由的单因素对照 |
| k=64 仍未达到 90% 点估计 | 预算仍不够，或 500 张 / 10 类的子集波动 | 用从 ImageNet 验证集随机抽取的预定 5,000 张评估；若仍未达标，诚实报告范围内未找到，不自动扩 k |

## 正式实验计划与预计耗时

推荐按原设计进入 P3，再进入 P4：保持所有方法、k、种子、m 和执行语义，只将数据换成 ImageNet 验证集中固定的 5,000 张。正式运行前在该子集重做 k=197 恒等检查，记录原模型准确率，然后执行同样的 35 组设置。

按本次 500 张耗时线性估计，本地 4060 的纯实验时间约 **28.5 分钟**。ImageNet 图片解码、HPC GPU 型号与环境会影响实际速度；可先用 50 张测吞吐，再估算正式运行时间。HPC 环境建立和数据准备另计。

检查点 3 的下一步选项：

1. **按原计划做 P3 / P4（推荐）**：将评估范围从 Imagenette 扩大到 ImageNet 的固定 5,000 张子集（994 类），形成正式 RQ1 结论；预计计算量为本次约 10 倍。首次 HPC 作业会提供具体脚本供审阅。
2. **先复核 K-means 的小 k 差异**：围绕已提出的原因设计一个单因素对照，预计实现与验证约半小时至一小时；可帮助解释原因，但会推迟主结果，需要先确认设计变更。

当前停在检查点 3，尚未运行 HPC 或 ImageNet 正式 RQ1，也未进入 RQ2。
