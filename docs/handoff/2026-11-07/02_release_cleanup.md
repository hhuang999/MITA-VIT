# 文件 02：第二阶段 · 整理成可开源的代码包

**目标：** 在新分支上得到一个干净的仓库：只包含论文用到的实验，代码精简，结构标准，并且论文里的每张表、每张图都能用它复现。

**一句话总结：** 以论文为准做减法，以复现为准做检查；整理只改“怎么组织”，不改“算出什么”。

---

## 0. 什么时候开始

**只有在作者明确说“开始第二阶段”之后才开始。** 作者可能同时给你一份更新过的论文草稿：
- 有新草稿，就以新草稿为准，并据此更新 04 号文件的清单（在汇报里列出你改了哪些行）。
- 没有新草稿，就以 03 号草稿 + 第一阶段结果为准：第一阶段的 X1–X7 和 E-C2 全部保留，它们进附录。

## 1. 三条原则

1. **论文是范围。** 只保留 04 号清单能追溯到的东西。
2. **行为不变。** 整理前后，同样的输入必须得到同样的输出（容差见第 6 节）。不顺手“改进”算法、默认参数或随机种子。发现原代码的 bug 时，先不改，记进汇报，由作者决定。
3. **证据不丢。** 事先登记是论文的重要卖点，它的证据是 `study/v5` 上的提交时间。所以：
   - 从 `study/v5` 拉新分支，**保留完整历史**，不压缩、不改写历史。
   - 不删除任何其他分支（包括 `study/v5`、`archive/pre-v5-2026-11-05`）。
   - 不推送。是否公开、推到哪里，由作者决定。

**分支名：** `release/v1`。

## 3. 第二步：目标结构

参考下面的结构。具体文件名可以按实际代码调整，但要保持“一个论文要素 → 一个配置 → 一条命令”。

```
README.md
LICENSE
CITATION.cff
pyproject.toml
requirements.txt                 # 锁定版本：PyTorch、timm 等
src/fastweight_vit/
    models/                      # 加载 DeiT-S/B、DINO+线性头、register 版本、MiTA-DeiT-S
    data/                        # ImageNet、ImageNet-S、ClickMe、部件标注的读取；固定名单
    readings.py                  # R0、C1、C2、C3 及替身；组合；GAE（参照）
    execution.py                 # 读取名单与执行检验、单层限制与删除
    diagnose.py                  # M1、M2、M3；高范数 token；值向量比例
    probes.py                    # 线性与 MLP 位置探针
    metrics.py                   # SRG、同距离富集、ClickMe 图片特异相关
    stats.py                     # 配对 bootstrap、“更高/相当/更低”判定
configs/                         # 每个论文要素一个 yaml
scripts/
    download_models.py
    prepare_data.py              # 下载说明、校验、生成固定名单
    run.py                       # 唯一的实验入口：python scripts/run.py --config ...
    make_tables.py               # 从运行输出生成全部表
    make_figures.py              # 从运行输出生成全部图
reproduce/
    from_outputs.sh              # 快速：从已保存的输出重建全部表和图
    full.sh                      # 完整：从头重跑全部实验
    smoke.sh                     # 冒烟测试：16 张图，几分钟内跑完
    colab.ipynb                  # 在 Colab L4 上运行 full.sh 的 notebook
data/splits/                     # 固定图片名单（只存图片 ID，不存图片）
results/                         # 每个实验的汇总 CSV；逐图输出见第 5 节
figures/                         # 论文图（图 1 除外，它是手画的）
docs/
    preregistration.md           # P1–P7、界限、冻结提交号与时间；探索性分析的登记
    reproduce.md                 # 论文要素 → 命令 → 输出 → 检查结果 → 耗时
tests/                           # 单元测试 + 冒烟测试
```

**命名：**
- 包名从 `mita_probe` 改为 `fastweight_vit`。原因：MiTA 是另一篇论文的名字，本论文的主题是快慢权重视角。
- 代码里的名字与论文一致：`R0`、`C1`、`C2`、`C3`、替身用 `stand_in_*`。旧编号（E3、S1、T7、A6、B24 等）不出现在代码和文件名里。
- 在 `docs/reproduce.md` 里放一张“旧名 → 新名”对照表，方便以后从 `study/v5` 查历史。

**不进入 `release/v1` 的目录：** `slides/`、课程资料、旧 notebook、`colab/` 下的旧运行脚本（只保留 `reproduce/colab.ipynb`）、`paper/`（论文 LaTeX 以后单独处理）。它们都留在 `study/v5`。

## 4. 第三步：精简代码

**删除：**
- 删除候选里的全部文件：实验、配置、脚本、函数、测试。
- 只被已删除实验使用的参数、分支和开关。
- 叙述过程的注释：版本号（v2、v3、v5）、“之前是……现在改成……”、TODO、被注释掉的代码、调试输出。
- 绝对路径（例如 `/content/drive/...`）、个人信息、令牌和密钥。

**保留：**
- 公开函数的 docstring：一句话说明做什么；参数不显而易见时说明参数和形状。
- 解释“为什么这样做”的注释，例如数值容差的理由、为什么用 float32。
- 冻结参数旁边的简短说明，例如 `# fixed before the main runs; see docs/preregistration.md`。

**不要做：** 重写算法、改变默认参数、合并“看起来差不多”的函数而改变数值、为了好看更换随机数的调用顺序。

**需要并入新代码的旧结果：**
- **扩展 B、扩展 C、top-k 图相似度（04 号清单 AB1–AB3）** 来自旧流程。用新代码重新实现并重跑。结果与旧结果相差超过第 6 节的容差时，不要强行对齐，写进汇报。
- **高范数 token 的值向量比例（0.2–0.3 倍）** 来自注意力预算研究 T3、T4。把这一个测量并入 `diagnose.py`，其余预算研究删除。
- **register 的 8 个 FFN 神经元** 由 T2 找到。保留找神经元的最小代码，并把找到的索引写进配置，注明来源。
- **MiTA-DeiT-S 的权重：** 如果是在本仓库训练的，保留最小训练脚本和配置；如果是下载的，保留下载脚本。无论哪种，都在汇报里说明权重目前存放在哪里、开源时需要放到哪里（由作者决定）。
- **复现检查（04 号清单 AC3）：** 它比较的是新旧两套代码，旧代码不进入 `release/v1`。保留它的结果 CSV，在 `docs/preregistration.md` 中作为历史检查说明，不保留旧流程。

## 5. 数据、模型与输出

- **数据集不随仓库分发。** `prepare_data.py` 给出下载地址、目录结构和校验方式（文件数或校验和）。ImageNet、ImageNet-S、ClickMe、部件标注数据各写清许可证和获取方式。
- **固定名单随仓库分发：** 执行检验的 5,000 张、ImageNet-S 固定 2,000 张、留出的 2,000 + 2,000 张、gallery 选图规则。只存图片 ID。
- **模型从官方来源加载**，在 `requirements.txt` 里锁定 timm 等版本。
- **输出：**
  - 汇总 CSV 全部放进 `results/`。
  - 逐图输出（`*.csv.gz`、`*.npz`）总大小在 100 MB 以内就放进 `results/`；超过就不放进 git，在 README 里写明“由 `reproduce/full.sh` 重新生成”，并在汇报里列出总大小，由作者决定是否另外托管。
- **第三方代码：** 如果有从其他仓库复制的代码（例如 GAE 的实现），保留原许可证声明，并在 README 中致谢。

## 6. 第四步：验证每张表、每张图都能复现

这是本阶段最重要的一步。三层检查都要做。

### 6.1 第一层：从已保存的输出重建（快）

- 用 `reproduce/from_outputs.sh`，从 `study/v5` 已有的运行输出重新生成全部表和图。
- **表：** 数值与 `study/v5` 上的版本完全一致。
- **图：** 图背后的数据 CSV 完全一致；图本身目视一致。

### 6.2 第二层：用新代码从头重跑（完整）

- 在一个**全新的克隆**里，只按 README 的步骤操作（新环境、`pip install -e .`、准备数据），运行 `reproduce/full.sh`。
- 与 `study/v5` 的逐图输出比较。

| 对象 | 容差 |
| --- | --- |
| 各读法、各指标的均值 | 绝对差 ≤ 1e-4 |
| “更高 / 相当 / 更低”判定、P1–P7 判定 | 完全相同 |
| 执行检验一致率 | 绝对差 ≤ 0.1 个百分点 |
| 重新训练的探针正确率 | 绝对差 ≤ 0.5 个百分点 |
| 依赖探针的读法（C2 及其组合）的均值 | 绝对差 ≤ 0.002 |

- **超出容差时：** 停下来找原因。不要为了通过而放宽容差。找不到原因就写进汇报，由作者决定。
- **算力：** 开始前估算总 GPU 时间。超过 24 小时（L4）时，先跑正文要素（F2a、F3、T1、N-RQ3、N-last），再跑附录要素，并在汇报中说明。

### 6.3 第三层：新环境冒烟测试

- 新虚拟环境，只安装 `requirements.txt`，运行 `pytest` 和 `reproduce/smoke.sh`。
- 冒烟测试用 16 张图，在 GPU 上 10 分钟内跑完，覆盖每一种读法、每一个指标和执行检验。
