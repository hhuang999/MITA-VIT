# 相关工作综述（阶段 2）

2026-10-29 · 完整的注释书目（英文，约 90 篇，每篇都打开原文页面核对过）：[方法与基线](research/methods_and_baselines.md)、[评估与数据集](research/evaluation_and_datasets.md)

## 一句话结论

"注意力 = 快权重 MLP"、MiTA 的读取机制，以及"深层只读少数 token"这几点，前人都已提出过。我们站得住的新意在于**检验方法**：
- 在官方预训练模型上做充分性和必要性检验；
- 把代价拆成稀疏、共享、压缩三部分；
- 用中心配对对照排除"物体在画面中间"；
- 在同一套检验下和常用解释方法正面比较。

## 1. 我们在文献中的位置

### 1.1 与 MiTA 本身的重叠（最需要正面回应）

MiTA 论文（Wen 等，arXiv 2602.01219，v6）已经做了下面这些事：

| MiTA 已有 | 我们不能再声称为新的 |
| --- | --- |
| 把注意力写成宽度为 N 的快权重 MLP，token 是隐藏神经元 | "注意力就是 MLP"这个视角 |
| 画出每个"专家"读取的 token 和分到的 query（图 3） | 读取名单的可视化本身 |
| 深层出现"token 剪枝效应"，集中在"与类别相关的区域"（图 4，在 MiTA 训练的模型上） | "深层聚焦主体"这个定性观察 |
| 用普通注意力训练的 DeiT-T/S，推理时直接换成 MiTA，仍保留 95% 以上性能（附录 C） | "不训练也能换成 top-k" |
| "性能对 k 比对 m 更敏感" | "稀疏比共享更关键"的趋势 |

我们新增的部分：

1. **问题不同**：MiTA 问的是"换掉后还准不准"（对标签的准确率）；我们问的是"换掉后还是不是原模型的判断"（与原模型的一致率），而且用的是官方的 DeiT-S 和 DINO 权重。
2. **损失拆解**：把代价拆成稀疏、共享、压缩三部分，并逐层分析。MiTA 只有"k 比 m 重要"的消融。
3. **必要性检验**：删除物体、背景和高范数 token，并配有随机对照和**中心配对**对照。
4. **定量检验"聚焦主体"**：在中心对照下，DeiT-S 深层的读取并不比"只看中间"更偏向物体。这直接修正了 MiTA 图 4 的定性印象，是一个真实的贡献。
5. **与解释方法比较**（RQ4）。

**写法建议**：把探针描述为"把 MiTA 的路由和压缩事后用作测量工具"，并明确致谢 MiTA 关于"无需训练即可替换"的观察。

### 1.2 "注意力 = 记忆 / 网络"的视角

| 工作 | 做了什么 | 和我们的关系 |
| --- | --- | --- |
| Schlag 等 2021（ICML） | 线性注意力等价于快权重编程器 | "快权重"视角的标准引用（注意它讲的是线性注意力） |
| Ramsauer 等 2021（Hopfield） | softmax 注意力等价于现代 Hopfield 网络的一步检索 | 读取名单可理解为被检索的"存储模式" |
| Geva 等 2021 | FFN 的隐藏单元是"键-值记忆"，可以逐个神经元解释 | 方向相反（FFN→注意力），但"逐个神经元解释"的方法先例 |
| Gupta 等 2021 | 预训练语言模型里，不训练直接换成每 query top-k 注意力 | "不训练也能用 top-k 执行"的先例（在文本上） |
| Irie 等 2022；Chen 等 2026 | 用 MLP↔注意力的对偶性做解释（语言模型） | 概念上最接近的"用对偶性做可解释性"，但都不在视觉上，也不检验读取集合是否充分 |

研究助理做了约 15 次针对性搜索，没有找到"把 ViT 的 token 当成注意力 MLP 的神经元，并检验这些神经元集合是否充分、是否必要"的工作。这只说明没搜到，不等于证明没有。

### 1.3 已有的"深层只读少数 token"观察

Ma 等 2022（FCViT）、DeepViT、GCNet 都报告过深层注意力与 query 无关、集中在少数 token 上；Darcet 等 2024 的高范数 token 也属此类。所以我们的 RQ2 是**确认性**的。新意在于：
- 把它量化为"共享读取的忠实性代价"；
- 检查被共享的 token 是物体还是高范数 token。

### 1.4 ViT 的解释方法（RQ4 的基线）

| 方法 | 需要梯度 | 选它的原因 |
| --- | --- | --- |
| 最后层 CLS 注意力 | 否 | "注意力即解释"的代表 |
| Attention Rollout（Abnar & Zuidema 2020） | 否 | 和我们一样不需要梯度、不需要类别 |
| GAE（Chefer 等 ICCV 2021） | 是 | 最常被引用的 ViT 解释方法之一，实现简单 |
| Grad-CAM（ViT 版） | 是 | 流行但在 ViT 上偏弱，作为常见参照 |
| Integrated Gradients | 是 | 经典的梯度归因 |
| 参照图：中心高斯、随机、真实物体掩码 | — | 必须有：文献显示很多指标连随机都难以超过 |

暂不采用：
- **AttnLRP**：它的库是否支持 timm 的 ViT 未核实；
- **ViT-CX**：每张图要几百到上千次前向；
- **TokenTM**：没有官方代码；
- **AttCAT**：只有文本代码。

可以在论文里列为相关工作。

**DINO 的特殊之处**：DINO 的官方线性头读的是最后 4 层 CLS 的拼接（已核对 eval_linear.py）。所以基于 CLS 注意力的方法要对这 4 层取平均；梯度方法会自动跟随分类头。

### 1.5 评估方法与陷阱

| 陷阱 | 来源 | 我们的做法 |
| --- | --- | --- |
| 把像素涂黑会产生"分布外"输入 | Jain 等 ICLR 2022；ROAD 2022 | 用**删 token**（在每层注意力中屏蔽），对 ViT 最自然。已用单元测试证明它与真正从序列中删除 token 完全一致 |
| 先删最重要的和先删最不重要的，两个结论可能矛盾 | ROAD；Blücher 等 2024 | 两种顺序都做，用 SRG = LIF − MIF 作为主数字 |
| 随机归因很难被超过 | SaCo（CVPR 2024） | 每个指标都配随机参照（5 个种子），并加 SaCo |
| 看起来合理 ≠ 模型真的依赖 | Adebayo 2018 | 把"合理性"（RQ3）和"忠实性"（RQ4）分开报告 |
| 中心偏差抬高定位分数 | Zhang 2016：VOC07 上"点中心"得 69.5%；Choe 2020：中心高斯在 ImageNet 上 52.5 MaxBoxAcc | 每个指标都和中心参照比；报告扣除中心后的分数、换掩码的 AUROC、同距离环内的富集；按物体位置和大小分层；做移位裁剪干预 |

### 1.6 需要回应的批评

- **深层 token 已不等于原图位置**（Meister 等 ACL 2021；Abnar & Zuidema 2020）；**高范数 token 会丢失位置信息**（Darcet 等 2024）。"神经元就是图块"这个前提需要检验。我们新增了 token 身份检验：逐层训练线性位置分类器，并计算与第 1 层同位置 token 的相似度。
- **"注意力不是解释"之争**（Jain & Wallace 2019；Wiegreffe & Pinter 2019）：我们的回应是不只看注意力，而是用充分性和必要性的行为检验。

## 2. 可以借鉴的改进

研究助理提出了 9 条，我按对本研究的价值排序：

1. **按"写出什么"而不只按"被读多少"给神经元打分**：用注意力 × value 向量长度。高范数 token 常常注意力高、value 小，这样可以减少它们的干扰。已实现为探针的 `value` 权重。
2. **区分物体和中心**：移位裁剪，把同一物体放到画面不同位置。已实现为 `shifted_crops` 实验。
3. **token 身份检验**：已实现为 `identity` 实验。
4. **按 head 分析**：Raghu 等 2021 发现浅层有局部 head 也有全局 head。对 head 取平均可能掩盖物体聚焦的 head。尚未实现，留作可选。
5. **因果替换代替删除**：用均值或其他图片的同位置 token 替换，而不是直接删除。尚未实现，留作可选。

## 3. 数据集结论

都能直接用现有的 ImageNet 分类头，不需要训练：

| 优先级 | 数据集 | 用途 | 状态 |
| --- | --- | --- | --- |
| 1 | **ImageNet-S919 验证集**（12,419 张，像素级掩码） | 物体聚焦是否超出中心；多物体图片；按位置分层；移位裁剪 | 加载器完成；标注 61 MB，已核对校验值；物体平均占 35.4% 面积 |
| 2 | **Hard ImageNet 验证集**（750 张） | 物体更小、更不居中，背景有强干扰 | 加载器完成；标注 65 MB，已核对；物体平均占 19.6% 面积 |
| 3 | **ClickMe 验证集**（约 1.7 万张，人类重要性图） | 与人类判断的一致性，自带中心对照 | 未实现；数据可下载（每个分片约 27 MB） |
| 4 | **PartImageNet**（部件掩码，158 类） | 部件层面：模型读的是头、身体还是尾巴 | 未实现；3.1 GB；注意它的图片来自 ImageNet **训练集** |

需要训练才能用，建议推后：Waterbirds、CUB 鸟种、Spawrious，以及按类别使用的 VOC/COCO。
